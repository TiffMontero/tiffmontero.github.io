## Artifact 1: Software Engineering and Design
### Project Files
- [Original Code](https://github.com/TiffMontero/CS499-Artifact1/tree/main/Artifact1%20Original)
- [Enhanced Code](https://github.com/TiffMontero/CS499-Artifact1/tree/main/Artifact1%20Improved)

The artifact I selected for the software design and engineering category is an inventory application from CS 360. The application was developed in Android Studio. Its purpose was to allow users to manage their inventory from a mobile device utilizing a login/registration screen for security. The users could add items, update item quantities, and receive SMS notifications when an item’s quantity reaches zero. The inventory information was stored locally utilizing a database. 
While I was satisfied with this application during the course, I also felt there were ways I could have improved it but simply lacked the knowledge and understanding to do so. Originally, the application displayed the inventory as a four-column grid and displayed the data as a list of strings. Deleting and editing items required selecting the item before clicking the icon, which felt unintuitive. 
For my enhancement, I changed the application, so each inventory item is represented as an object within a row instead of individual cells. Each row contains edit and delete icons, which skips the selection process, further reducing the number of clicks needed to complete the task. This also frees up the top navigation portion, which looked a bit crowded with 3 icons there. When editing, all 3 fields can now be modified. I also added a live search feature that filters records by item name. The search is case-insensitive. In addition, all CRUD functionalities are now in InventoryDatabase, which better organizes the code. 
In addition, error handling was added, as most of the error messages were toast notifications. Now, leaving a blank or incorrect field highlights where the error is located. Negative costs and quantities have an added layer of security with proper error handling. This upgrade was also included in the login page, where now passwords require 6 characters.  
The enhancements supported the course outcomes originally selected, specifically outcomes 3 and 4. The restructuring of the inventory display and addition of search functionality supports this. Outcome 4 focuses on using tools and techniques to develop solutions that provide value. This was demonstrated with the improved interface controls which makes the application more intuitive and easier to use and maintain. 
This enhancement was both challenging and rewarding. One of the biggest challenges for me was changing the inventory display. Going from individual cells to a row for each item required a lot of trial and error. I also learned that just because my application works, it doesn’t mean it was built well. I had the update and delete functions inside of MainActivity because it made sense to me at the time. However, separating CRUD functions would be infuriating for someone else to have to update, as they would have to search through the entire codebase to find it. This would be more time consuming as applications get larger. I do feel there could be more improvements to be made, such as proper encryptions for logins and adding sorting options, but overall, I am very happy with the changes that were made.

## Artifact 2: Algorithms and Data Structures

The artifact I selected for the algorithm and data structure update is the Grazioso Salvare project from CS 340. The project uses Python, MongoDB, and Dash to create a database that displays animal shelter records. Users can filter different items, which updates a pie chart of all breeds and their location. 
I chose this project because it works with a large database, which gives more opportunities for errors and can benefit the most. A search bar was added, allowing users to search for animals by either breed or name. In addition, a sorting dropbox was also implemented. It allows the user to sort by name, breed, age, or outcome date. A result counter was also added, since there wasn’t one to start with. Both the map and pie chart automatically update when these filters are applied. The CRUD functions were also updated to reject empty fields, which could have caused someone to accidentally delete the entire database.
The outcomes I chose for this artifact were three and four, I believe I have met those requirements. Outcome three was met by improving how the program filters, sorts, and searches the database. I met outcome four by using multiple software development tools to improve usefulness and interaction in the dashboard. 
One thing I learned is even though filtering options are helpful, there is such a thing as too much, which can make the dashboard cluttered. In this case, after applying the new updates, I felt the radio options were unnecessary. While I did consider deleting them, I ultimately decided not to in order to show my previous work next to my improvements for the purpose of this assignment.
My biggest challenge was setting up this project on my computer since we originally worked on it in Apporto. I also have an older Macbook, which added limits with dependencies I was able to utilize. Setting it up took a lot of trial and error, which was pretty time consuming.

## Artifact 3: Databases
### Project Files
- [Original Code](https://github.com/TiffMontero/CS499-Artifact2And3/tree/main/original)
- [Enhanced Code](https://github.com/TiffMontero/CS499-Artifact2And3/tree/main/enhanced)

The artifact I selected for the database component is the Grazioso Salvare project from CS 340. The project uses Python, MongoDB, and Dash to create a database that displays animal shelter records. Users can filter different items, which updates a pie chart of all breeds and their location. It contains CRUD operations to allow the users to interact with the database.
I selected this artifact because it allowed me to demonstrate my growth in database skills and improved how the application manages it. All four CRUD methods were improved to include input validation, which fixed a bug with the original read method. The input validation also prevents users from accidentally modifying or deleting all records. Finally, update_one and delete_one were added to give an option which only modifies one record instead of multiple. 
The course outcomes previously decided were four and five. Outcome four was met by utilizing MongoDB and Python to improve the database’s existing functionality. Outcome five was met by adding input validation to safeguard against accidental mass edits and deletions to the entire database. 
This artifact update helped me better understand how lack of input validation could cause accidents to entire databases. While this may just be a project with no real repercussions, a company’s database being accidentally modified or deleted could cause a halt in services, business, and overall income. I also created new records and used those to test the new methods instead of altering the existing database, which were later deleted. Overall, this enhancement helped me understand how sometimes seemingly simple and small changes can greatly increase an application’s reliability and security.
